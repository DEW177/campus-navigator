# SC09 อาคารวิทยวิภาส

Owner-supplied reference data for the real building. It is separate from DEMO.
The app lists 32 named rooms/areas visible in the supplied drawings and displays
five floor plans. Unnumbered faculty offices are visible in the floor-3 image;
individual office numbers and door positions have not been inferred.
LEC 9107/9108 are in the separate approach drawing, not in the department plan.

## Destination and entrance

The owner accepted the building location in
<https://maps.app.goo.gl/w9RiY3P5ZWZWrbyJ6> as the available outdoor destination.
The link's place coordinates are **16.4756894, 102.8251242**. Its Street View
camera coordinates are not used as the destination. This is a building-area
pin, not a surveyed entrance, parking point, or verified vehicle drop-off.
The API identifies it as `destination_kind="building"`; the UI labels it accordingly.

The approach drawing shows the building entrance, lobby lift/display cabinet,
and department entrance. The owner confirmed that the department entrance connects
to the lower-left door on the floor-1 department plan. See
[`approach.png`](../backend/app/static/sc09/approach.png) and the supplied
[`floor-1-entry.png`](../backend/app/static/sc09/floor-1-entry.png).
These drawings establish a connection, not measured distances or GPS positions.
The approach image and description are displayed separately beneath the outdoor map.

## Import / start

Docker Compose runs migrations and both independent importers on startup:

```powershell
docker compose up -d --build
```

For a non-Docker installation, from `backend/`:

```bash
python -m app.migrations.upgrade
python -m app.database.load_sc09
```

Both a fresh database and an existing Docker database are supported; no volume
deletion is needed. Repeated imports preserve an existing SC09 building, its
records, and any later surveyed edits. A conflicting DEMO record using code SC09
fails explicitly. Future dataset changes require a reviewed update/import, rather
than silently replacing an existing building on every startup.

## What works

- Search SC09, วิทยวิภาส, or a visible room number such as 9228.
- Open the selected room, browse all five floor plans, and zoom/pan the images.
- Use GPS, address search, or a manual pin to plan a driving route to the building
  area (Geoapify key required for in-app address search/routing).
- Open the driving destination in Google Maps; inspect the approach drawing.

## Indoor routing pending survey

The source drawings have no verified scale and most room doors are not marked.
There are deliberately **no invented door nodes, corridor edges, vertical
distances, room markers, or indoor routes** for SC09. Room labels are readable
in the images; selection from the room list does not imply a surveyed door.
The importer marks these floors `routing_ready=false`. `/api/floors/` returns
`meters_per_unit=null` and metric routing rejects these reference plans even if
someone accidentally adds graph edges. Existing DEMO routing stays available.

The legacy database's positive, non-null scale column retains an unused value of
1 for reference plans; it must never be interpreted as metres per pixel. The API
masks it and the routing guard blocks its use. Before enabling SC09 routing:

1. Verify the current drawings and room names on site.
2. Prepare measured/scaled floor plans (the hand-drawn approach may need redrawing).
3. Confirm each door, corridor turn, usable stair/lift landing and restriction.
4. Measure horizontal and vertical distances, create graph connections, and bind
   rooms to their actual door nodes and the designated indoor entrance.
5. Set the correct scale and enable `routing_ready` only after route verification.

## Asset provenance

Plans and annotations were supplied by the repository owner in this task.
`floor-1.png` … `floor-5.png` are standalone raster crops of the supplied drawings,
with the same viewport dimensions as the original SVGs. The floor API translates
legacy SC09 SVG URLs to these PNGs, including existing databases; no reimport or
volume deletion is needed. DEMO SVGs are unchanged.

`floor-1.svg` … `floor-5.svg` are retained SVG viewports containing the original raster
drawings, one floor per viewport; geometry and labels were not redrawn or treated
as to-scale measurements. `approach.png` and `floor-1-entry.png` are unchanged
owner-supplied images. These are reference plans, not official surveyed drawings.
